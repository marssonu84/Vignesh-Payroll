Vighnesh Payroll Systems V10.30

Deployment
1. Back up the current site and database first.
2. Upload over the existing web root. Keep the server's existing Database.config (not included here).
3. Database.config.template holds placeholders only; never upload it as Database.config.
4. Open Database Manager and run Test Connection before any schema action.
5. Read TWO_STEP_LOGIN_README.txt, then test on a copy before enabling for admins.

  unused music files/scripts/handler, superseded V10.22 notes.

V10.25 change (entity Pending lock)
- Login is refused while the client's entity (Tenants.ApprovalStatus) is Pending, Rejected or otherwise not Active.
- The check now runs after the password is verified (no status leak to strangers) and before the user-active check,
  so a newly registered entity sees "pending approval" instead of "user account is inactive".
- An already signed-in session ends on its next request if the entity stops being Active (Auth.IsLoggedIn, cached per request).
- Login.aspx?pending=1 (sent after Signup) now shows a pending-approval message.
- Super User (no entity) is never blocked. Note: there is no separate subscription/payment status in the database;
  "Pending" here means the entity registration awaiting Super User approval.

V10.26 change (Set to Pending / Suspend)
- Entities page (Super User): Status column is now colour-coded (Active green, Pending amber, Suspended red, Rejected grey).
- New buttons on an Active entity: "Set to Pending" and "Suspend" (both ask for confirmation). Login is refused for all users
  of that entity and signed-in users are logged out on their next request. No users or data are changed or deleted.
- New button "Reactivate" on a Suspended entity; "Approve" still handles Pending/Rejected entities.
- Status values: Active, Pending, Suspended, Rejected (stored in the existing Tenants.ApprovalStatus column - no database change).
- Every change is written to OrganisationAudit.

V10.27 change (Backup / Export)

- NEW: "Download Entity Data (ZIP)" - one entity's data as CSV files (entity, branches, users without passwords, permissions,

- Page explains full backup/restore via the host control panel or SSMS (.bacpac / Generate Scripts). Restore is not done in-app.

V10.27 change (entity data export)

V10.31 (attendance statement format + payroll alignment)
- Attendance > Monthly Attendance Summary now shows the printable "Staff Salary Disbursement" statement:
  S.No | Name of the Staff | Lates | Leaves | Permissions | Amount to be Deducted /Days Present.
  Entity name/address/phone come from the entity record; the disbursement date (default: 4th of the month after the
  attendance month, editable) prints with its weekday; one block per branch, S.No restarts per block; zero = blank cell.
  New "Print Statement" button (prints only the statement). The old detailed columns moved under "Detailed attendance breakdown".
- RULE CHANGE: Leaves = Casual Leave + Absent + Half Days. Leaves + (Lates / 3, whole groups) + (Permissions / 2 pairs x 0.5)
  are added and the first 1 day each month is free; only the balance is deducted. Before, Absent days were deducted in full
  (no free day). Months finalised under V10.30 keep their old snapshot until Attendance is re-finalised.
- Payroll grid now shows Lates, Leaves, Permissions and Amount to be Deducted (days) from the finalised attendance snapshot
  (read-only, also for saved payroll). Days in Month auto-fills from the salary month on Load.
- No database change.

V10.31 change (Staff Salary Disbursement Excel statement)
- NEW App_Code/StatementExcelService.cs: builds the statement as .xlsx in the same layout as the paper sheet
  (organisation heading, disbursement date line, branch heading, S.No / Name / Lates / Leaves / Permissions /
  Amount to be Deducted, footnote). One worksheet per branch. Column F is a live Excel formula:
  =MAX(0,Leaves+INT(Lates/3)+INT(Permissions/2)*0.5-1); zero shows blank.
- Attendance page: new button "Download Statement (Excel)" (uses the month, branch and disbursement date on screen).
- Payroll page: new button "Download Salary Statement (Excel)" (uses the finalised Attendance snapshot, so it always
  matches what Payroll deducts; disbursement date = 4th of the following month).
- No database change. No change to existing calculations.
